## Executive Summary

This update covers a focused set of changes that consolidate path normalization logic and improve symlink handling consistency. The main theme is **centralization of path normalization** into a single `_normalize_path_in_manifest()` function in `_manifest.py`, eliminating duplicate implementations across multiple operation modules.

## Key Changes

### 1. Centralized Path Normalization

**Before:** Each operation module had its own path normalization function:
- `_join_manifest.py` had `_normalize_prefix()`
- `_partition_manifest.py` had `_normalize_path()`
- `_subtree_manifest.py` had `_normalize_subtree_path()`
- `_collect_abs_snapshot_symlinks.py` had `_remove_longpath_prefix()`

**After:** All path normalization is now handled by a single function in `_manifest.py`:

```python
def _normalize_path_in_manifest(path: str) -> str:
    """
    Normalize a path for storage in a manifest.

    All paths in manifests use a consistent normalized format:

    Path Separator:
        - POSIX forward slash '/' is used as the path separator on all platforms
        - On Windows, backslashes are converted to forward slashes (directory separators)
        - On POSIX, backslashes are preserved (valid filename characters)

    Path Components:
        - '.' and '..' components are collapsed via posixpath.normpath
        - Trailing slashes are removed (except for root paths)

    Windows Long-Path Prefix:
        - The '\\\\?\\' prefix is stripped on Windows
        - The '//?/' prefix is also stripped on Windows

    Examples:
        - 'C:\\Users\\name\\file.txt' -> 'C:/Users/name/file.txt' (Windows)
        - '\\\\?\\C:\\Users\\name\\file.txt' -> 'C:/Users/name/file.txt' (Windows)
        - '/home/user/../user/file.txt' -> '/home/user/file.txt' (POSIX)
        - 'path/to/./file.txt' -> 'path/to/file.txt'
    """
    if os.name == "nt":
        # Strip Windows long-path prefix if present
        if path.startswith("\\\\?\\"):
            path = path[4:]
        elif path.startswith("//?/"):
            path = path[4:]
        path = path.replace("\\", "/")
    normalized = posixpath.normpath(path)
    return normalized
```

**Impact on rusty-attachments:**
- The Rust implementation should have a single `normalize_path_in_manifest()` function
- This function should handle Windows long-path prefix stripping (`\\?\` and `//?/`)
- The function should be used consistently across all operations

### 2. Enhanced `_is_absolute_path()` Documentation

The `_is_absolute_path()` function now has comprehensive documentation:

```python
def _is_absolute_path(path: str) -> bool:
    """
    Check if a path string represents an absolute path.

    A path is considered absolute if:
        - It starts with '/' (POSIX absolute or Windows UNC path)
        - On Windows: it starts with a drive letter followed by ':' (e.g., 'C:', 'C:/')

    Examples of absolute paths:
        - '/home/user/file.txt' (POSIX)
        - 'C:/Users/name/file.txt' (Windows drive)
        - 'C:' (Windows drive root)
        - '//server/share/file.txt' (Windows UNC)

    Examples of relative paths:
        - 'project/file.txt'
        - './file.txt'
        - '../parent/file.txt'
    """
```

### 3. Symlink Target Handling Refactored to Use Strings

**Before:** Symlink target paths were passed around as `Path` objects:

```python
def _get_symlink_absolute_target(full_path: Path) -> Path:
    """Get the absolute path of a symlink's target without resolving symlink chains."""
    target = full_path.parent / os.readlink(full_path)
    target_clean = _remove_longpath_prefix(target)
    return Path(os.path.normpath(target_clean.absolute()))
```

**After:** Symlink targets are now normalized strings:

```python
def _get_symlink_absolute_target(full_path: Path) -> str:
    """Get the absolute path of a symlink's target as a normalized string.

    Returns a normalized path string suitable for use in manifests and
    string-based path comparisons.
    """
    target = full_path.parent / os.readlink(full_path)
    return _normalize_path_in_manifest(str(target.absolute()))
```

**Cascading changes:**
- `transitive_targets` list changed from `List[Path]` to `List[str]`
- `escaping_dir_symlinks` list changed from `List[Tuple[str, Path]]` to `List[Tuple[str, str]]`
- `is_path_in_collected_set` callback changed from `Callable[[Path], bool]` to `Callable[[str], bool]`
- All symlink target comparisons now use normalized strings

**Impact on rusty-attachments:**
- Symlink targets should be stored and compared as normalized strings, not `PathBuf`
- This simplifies comparison logic and ensures consistent normalization

### 4. Removed `ManifestEntry` Type Alias from Filter Module

**Before:** `_filter_manifest.py` defined a local type alias:

```python
ManifestEntry = Union[ManifestFilePath, ManifestDirectoryPath]
```

**After:** The type alias is removed; functions use the union type directly:

```python
def filter_manifest(
    manifest: M,
    entry_filter: Callable[[Union[ManifestFilePath, ManifestDirectoryPath]], bool],
) -> M:
```

**Rationale:** The type alias was only used in one module and wasn't exported. Using the explicit union type improves clarity.

### 5. Cycle Detection Uses Normalized Strings

The cycle detection in `_collect_transitive_target()` and `_collect_escaping_dir_symlink()` now uses normalized path strings instead of `Path` objects:

```python
# Before
target_posix = target_path.as_posix()
if target_posix in _visiting:
    ...
_visiting.add(target_posix)

# After
if target_path in _visiting:  # target_path is already a normalized string
    ...
_visiting.add(target_path)
```

This simplifies the code since paths are already normalized when passed to these functions.

### Implementation Notes for Rust

1. **Path Normalization Function:**
```rust
/// Normalize a path for storage in a manifest.
/// 
/// - On Windows: strips `\\?\` and `//?/` prefixes, converts `\` to `/`
/// - On all platforms: collapses `.` and `..` components
pub fn normalize_path_in_manifest(path: &str) -> String {
    let mut path = path.to_string();
    
    #[cfg(windows)]
    {
        // Strip Windows long-path prefixes
        if path.starts_with("\\\\?\\") {
            path = path[4..].to_string();
        } else if path.starts_with("//?/") {
            path = path[4..].to_string();
        }
        path = path.replace('\\', "/");
    }
    
    // Use a POSIX-style normpath equivalent
    normalize_posix_path(&path)
}
```
