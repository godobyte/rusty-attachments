**Date:** 2026-01-23

## Executive Summary

The Python Snapshots library has matured significantly since the 2026-01-10 design documents. The implementation is now feature-complete with full job submission and download integration behind a feature flag (`ENABLE_SNAPSHOTS_LIBRARY=1`). Key additions include:

1. **Full job submission integration** - The snapshots library can now handle the complete job submission workflow
2. **Download integration** - `download_abs_manifest` operation with multi-part and chunked file support
3. **Progress tracking overhaul** - Detailed progress callbacks with separate hashing/uploading phases
4. **S3 check cache validation** - Probabilistic verification to detect stale cache entries
5. **v2023 manifest conversion** - Bidirectional conversion between snapshots classes and legacy format

## Deviations from 2026-01-10 Design

### 1. Operation Naming Changes

The design document used generic names, but the implementation uses more specific names:

| Design Document | Actual Implementation | Notes |
|-----------------|----------------------|-------|
| `collect_manifest()` | `collect_abs_snapshot()` | Emphasizes absolute paths |
| `hash_manifest()` | `hash_abs_manifest()` | Emphasizes absolute paths |
| `hash_upload_manifest()` | `hash_upload_abs_manifest()` | Emphasizes absolute paths |
| `download_manifest()` | `download_abs_manifest()` | Emphasizes absolute paths |
| `compute_diff_manifest()` | `diff_snapshots()` | Clearer naming |

### 2. Progress Callback Interface

The design mentioned `print_function_callback` throughout. The implementation has **removed** this in favor of structured progress callbacks:

```python
# Old (removed):
print_function_callback: Callable[[Any], None] = lambda msg: None

# New:
on_progress: Optional[HashUploadProgressCallback] = None

# Where HashUploadProgressCallback is:
Callable[[HashUploadProgressMetadata], bool]  # Return False to cancel
```

**HashUploadProgressMetadata** now includes:
- `total_file_chunks`, `total_bytes` - Total work
- `hashed_file_chunks`, `hashed_bytes` - Hashing progress
- `hash_skipped_file_chunks`, `hash_skipped_bytes` - Hash cache hits
- `uploaded_file_chunks`, `uploaded_bytes` - Upload progress
- `upload_skipped_file_chunks`, `upload_skipped_bytes` - S3 cache hits
- `progress` (0-100), `progressMessage` - Human-readable status
- `total_time`, `transfer_rate` - Performance metrics (new!)

### 3. S3 Check Cache Validation

Not in original design. The implementation adds probabilistic verification:

```python
# S3DataCache now validates cache entries probabilistically
# If a cached "exists" entry is found to be stale, the entire cache is invalidated
```

This prevents issues where files were deleted from S3 but the local cache still reports them as present.

### 4. Account ID Handling

The design didn't specify account ID handling. Implementation adds:

```python
NO_ACCOUNT_ID_CHECK = ""  # Sentinel to skip account ID verification

S3DataCache(
    s3_bucket=...,
    s3_key_prefix=...,
    s3_client=...,
    s3_check_cache=...,
    account_id=NO_ACCOUNT_ID_CHECK,  # or actual account ID
)
```

### 5. v2023 Manifest Conversion

New module `_convert_v2023_manifest.py` provides bidirectional conversion:

```python
# Snapshot → v2023 (lossy: drops symlinks, empty dirs, chunked files)
snapshot_to_v2023_manifest(snapshot: Snapshot) -> AssetManifest

# v2023 → Snapshot (lossless for supported features)
v2023_manifest_to_snapshot(manifest: AssetManifest) -> Snapshot
```

### 6. Job Submission Integration

The design showed workflows but not integration. Implementation adds:

- `_process_job_attachments_with_snapshots()` in `_submit_job_bundle.py`
- `partition_snapshot_by_storage_profile()` in `_upload_v2.py`
- Feature flag: `ENABLE_SNAPSHOTS_LIBRARY = os.environ.get("ENABLE_SNAPSHOTS_LIBRARY") == "1"`

### 7. Download Integration

New `_download_v2.py` module integrates snapshots download:

```python
# In download.py:
if ENABLE_SNAPSHOTS_LIBRARY:
    from ._download_v2 import download_files_from_manifests_v2
    return download_files_from_manifests_v2(...)
```

## New Features Not in Original Design

### 1. Sliding Window Transfer Rate

Progress callbacks now include real-time transfer rate calculation using a sliding window:

```python
# In _HashUploadProgressState:
_transfer_rate_window: List[Tuple[float, int]]  # (timestamp, bytes)
_transfer_rate_window_duration: float = 5.0  # seconds
```

### 2. Multi-Part Upload/Download

Both upload and download now support multi-part transfers for large files:

- **Upload**: Files > threshold use multi-part upload with concurrent parts
- **Download**: Large files downloaded in parallel byte-range requests

### 3. Sparse File Pre-allocation

Downloads pre-allocate files as sparse to improve performance:

```python

def preallocate_file(path: Path, size: int) -> None:
    """OS-specific sparse file allocation."""
```

`collect_abs_snapshot` now detects and handles symlink cycles:
